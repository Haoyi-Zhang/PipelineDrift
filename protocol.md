# Frozen evaluation protocol

## 1. Claim under test

For a bounded deterministic declaration, compile candidate retention atoms and
planned monitor updates to finite machines.  Decide whether a selected atom set
preserves every update's replay behavior for all histories and all future
records; synthesize the minimum positive-cost safe set; and explain failure with
a replayable paired-history/common-future certificate.  Evaluation checks the
implementation of this claim.  It does not test production workload prevalence,
throughput, model accuracy, probabilistic drift detection, or user outcomes.

The portfolio protocol was frozen before the complete campaign.  Corrections to
two implementation defects found in source audit preceded all recorded
portfolio results: duplicate separator masks are now retained only once across
updates, and equal-primary-cost branches are not pruned before deterministic
cardinality/mask tie-breaking.  Tests cover both repairs.  A later artifact audit found two certificate-layer
issues before the final recorded campaign: the positive certificate omitted the
obstruction basis and reachable-fiber migration representatives described by the
paper, and Python Boolean values could alias integer states in malformed
certificates.  The final schema now carries those objects, the independent
verifier recomputes them, rejects undeclared fields and uses exact integer type
checks, and dedicated mutation tests cover each failure mode.

## 2. Complete finite catalogues

### Unary-complete catalogue

Use historical and future alphabets of size one, two candidate binary-state
retention machines, and one binary-state update.  Enumerate every transition
encoding for the two atoms, historical target, future target, and binary output,
with fixed initial state zero.  This yields 4,096 candidate catalogues.  Check
all eight portfolios per catalogue: 32,768 masks total.

### Binary-complete subspace

Use historical and future alphabets of size two.  The catalogue has two
one-state-or-two-state candidate atoms from the fixed subspace generated by the
campaign encoder and one two-state update.  Enumerate all 16,384 problem
encodings and all four portfolios each: 65,536 masks.  Exact encodings and
iteration order are retained in the CSV result.

For every problem/mask, an independent product-state safety checker is compared
with the separator-hitting decision.  For every feasible catalogue, exhaustive
portfolio enumeration is compared with the branch-and-bound optimizer under the
order `(total cost, number of atoms, numeric mask)`.  For every emitted failure,
the independent certificate verifier replays both histories and the common
future.  In the complete unary catalogue, direct bounded word enumeration also
checks globally minimum certificate length.

Stop and repair on any safety disagreement, optimizer disagreement, invalid
certificate, nonminimum unary witness, incomplete catalogue, or resource guard.
No mismatch may be filtered or replaced.

## 3. Named declarations

The 12 declarations in `declarations/` were selected before the final campaign
to exercise distinct evolution mechanisms:

- schema rename and field deletion;
- changed count/threshold families;
- class/slice coverage and shared summaries;
- missingness streaks and rolling patterns;
- label revision and joint-label disagreement;
- marginal summaries that cannot recover a joint statistic;
- a weighted set-cover trap for the greedy baseline.

The compiler rejects unknown fields, unsupported operators, nonfinite domains,
nonpositive costs, oversized schemas/states, and malformed transitions.
Declarations are examples of finite software-pipeline monitoring needs, not a
random sample of deployed pipelines.

### Baselines

1. **Per-update union:** solve each update separately and retain the union.
   This is always safe when each update is feasible, but can lose cross-update
   sharing and therefore be nonoptimal.
2. **Greedy:** repeatedly choose the atom with best newly-hit-obstruction per
   unit cost, using deterministic ties.  It provides an upper bound, not an
   optimality guarantee.
3. **All candidates:** tests catalogue feasibility.  It is not safe when a zero
   separator exists.

## 4. Independent language check

`tools/check_language.py` loads each declaration through the compiler and also
through `drift_contracts/dsl_reference.py`, which does not import compiler
transition constructors.  For every finite atom state and historical record,
and every update state over historical and future records, it compares the
compiled table cell to a direct primitive evaluation.  It also compares every
monitor output cell.  The frozen report covers 528 retention transitions, 498
monitor transitions, and 91 outputs: 1,117 cells total.

## 5. Mutation protocol

For each named declaration, mutate exactly one valid cell of one monitor update:
one historical transition, future transition, or output at a time.  Replace the
cell with every other valid state/output value.  Deduplicate identical compiled
problems.  Do not mutate candidate atoms or costs.  For each of the 571 retained
mutations:

- recompute catalogue feasibility and the exact optimum;
- check whether the original optimum remains safe;
- record optimum-cost increase/decrease when both are feasible;
- verify every failure certificate independently.

This protocol measures sensitivity inside the shipped finite models.  It does
not model a probability distribution over real software changes.

## 6. Preserved single-summary regression

The original foundation remains a regression, not the new contribution.  It
includes every total deterministic specification with initial state zero in:

- unary alphabet, retained states 1 or 2, target states 1, 2, or 3;
- binary alphabet, retained states 1 or 2, target states 1 or 2.

All retention, historical-target, future-target tables and output vectors are
included: 46,932 cases.  An independent oracle enumerates every migration map
and complete finite history/future bounds.  It checks admission, certificate
validity, and minimum rejection length.  Type-only, current-output-only, and
literal-state baselines are counted over the same space.  A separate 48-point
saturated-counter family checks the closed-form boundary.

## 7. Certificate verification contract

An optimal certificate contains exactly the selected mask, selected atom names,
declared cost, the inclusion-minimal obstruction basis, and one reachable-fiber
representative map per planned update.  The verifier independently recomputes
future equivalence, product reachability, the obstruction basis, portfolio
safety, all reachable selected-summary fibers, and the deterministic
cost/cardinality/mask optimum by exhaustive subset enumeration.  It requires an
exact schema and exact integer types; in particular, JSON/Python Boolean values
are not accepted as integer masks or states.

An unsafe certificate additionally binds the selected mask and contains the
update name, two historical words, one common future word, the recomputed
separator, target endpoints, and event cost.  The verifier replays all atom and
target transitions from the declaration and requires unequal final outputs.
These checks establish consistency with the compiled finite declaration; they
do not validate an external pipeline implementation.

## 8. Resource and determinism contract

All runs are local, CPU-only, single-worker, and use the Python standard library.
The reproduction runner attempts to pin one CPU, applies a 3 GiB address-space
limit and a 60-second child CPU limit, starts one child at a time, and requires a
new output directory.  The project-wide ceilings remain four CPU cores, 4 GiB
RAM, no swap/GPU/API, 45 minutes per individual run, and eight CPU-hours total.

The runner compares 18 scientific records byte-for-byte and compares aggregate
scientific fields after removing fresh timing/RSS observations.  Timings are
measurements, not correctness criteria.  Successful re-execution does not turn
finite checks into a general mechanized proof or an internal audit into
independent review.
